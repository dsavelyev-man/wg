# addPeer

Add a peer to a WireGuard configuration file with automatic IPv4 or IPv6 address allocation.

## Signature

```ts
import type { AddPeerOptions, AddPeerResult } from "@kriper0nind/wg-utils"

addPeer(filepath: string, options: AddPeerOptions): Promise<AddPeerResult>
```

```ts
interface AddPeerOptions {
  publicKey: string
  presharedKey?: string
  persistentKeepalive?: number
  allowedIPs?: string | string[]
  endpoint?: string
  allowedApps?: string
  family?: "ipv4" | "ipv6"
  addressPool?: string
  iface?: string
  sync?: boolean | "auto"
}

interface AddPeerResult {
  ip: string
  address: string
  family: "ipv4" | "ipv6"
  peer: WireGuardPeer
}
```

## Basic usage

```ts
import { addPeer } from "@kriper0nind/wg-utils"

const result = await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: clientPublicKey,
  persistentKeepalive: 25,
})

console.log(result.ip) // 10.0.0.2
console.log(result.address) // 10.0.0.2/32
console.log(result.family) // ipv4
```

## Automatic allocation

`addPeer()` reads the existing file and derives the address pool from the matching `Interface.Address` value.

- IPv4 addresses are allocated as `/32`.
- IPv6 addresses are allocated as `/128`.
- Used interface and peer addresses are skipped.
- The first free address is allocated.
- IPv4 is selected by default when an IPv4 interface address exists.
- `AddressPoolExhaustedError` is thrown when no address is available.

### IPv6

```ts
const result = await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: clientPublicKey,
  family: "ipv6",
})

console.log(result.address) // fd00::2/128
```

### Custom pool

```ts
const result = await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: clientPublicKey,
  addressPool: "10.10.0.0/24",
})
```

The explicit pool must match the selected address family.

## Custom routes

When `allowedIPs` is provided, it is used exactly as the peer's route list. The first entry is also used to populate `result.ip`, `result.address`, `result.family`, and `result.peer`.

```ts
const result = await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: clientPublicKey,
  allowedIPs: ["10.0.0.50/32", "192.168.10.0/24"],
})
```

## Optional peer fields

```ts
const result = await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: clientPublicKey,
  presharedKey: presharedKey,
  persistentKeepalive: 25,
  endpoint: "vpn.example.com:51820",
  allowedApps: "android",
})
```

`AllowedApps` is preserved as extra metadata for downstream tooling. WireGuard itself ignores unknown keys.

## Sync behavior

`AddPeerOptions` extends `SyncOptions`:

- `sync: false` updates only the file.
- `sync: true` syncs the configured interface.
- `sync: "auto"` or omitted syncs only when the interface is already running.
- `iface` overrides the interface name derived from the file name.

```ts
await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: clientPublicKey,
  sync: "auto",
})
```

## Generated peer

```ini
[Peer]
PublicKey = client-public-key
PresharedKey = optional-preshared-key
AllowedIPs = 10.0.0.2/32
Endpoint = vpn.example.com:51820
PersistentKeepalive = 25
AllowedApps = android
```

## Errors

- `ConfigValidationError` for a missing public key or invalid options
- `PeerAlreadyExistsError` for a duplicate public key
- `AddressPoolExhaustedError` when no address is available
- Node.js file-system errors for missing files or insufficient permissions
- `CommandError` when an explicitly requested sync fails
