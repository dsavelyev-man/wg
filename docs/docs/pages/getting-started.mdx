# Getting Started

`@kriper0nind/wg-utils` is a TypeScript library for managing WireGuard configuration files, peers, keys, client profiles, and interfaces.

## Installation

```bash
npm install @kriper0nind/wg-utils
```

For a local checkout:

```bash
npm ci
npm run check
```

## Requirements

- Node.js 20 or newer
- `wg` for key generation and live interface inspection
- `wg-quick` for interface management on Linux and macOS
- Root/sudo privileges for system interface operations
- `iptables` for the default NAT rules generated by `initConf`

Check whether the WireGuard CLI is available:

```ts
import { checkWg, requireWg } from "@kriper0nind/wg-utils"

if (!(await checkWg())) {
  await requireWg() // throws a descriptive error
}
```

You can override executable locations:

```bash
WG_UTILS_WG_PATH=/usr/bin/wg
WG_UTILS_WG_QUICK_PATH=/usr/bin/wg-quick
WG_UTILS_WIREGUARD_PATH="C:\\Program Files\\WireGuard\\wireguard.exe"
```

## Create a server and client

```ts
import {
  addPeer,
  generateClientConfig,
  generateClientQRCode,
  generateKeys,
  initConf,
  up,
} from "@kriper0nind/wg-utils"

const serverKeys = await generateKeys()
const clientKeys = await generateKeys()

await initConf("/etc/wireguard/wg0.conf", {
  privateKey: serverKeys.privateKey,
  ip: "10.0.0.1",
  port: 51820,
  interface: "eth0",
  dns: "1.1.1.1",
})

const peer = await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: clientKeys.publicKey,
  persistentKeepalive: 25,
})

const clientConfig = generateClientConfig({
  privateKey: clientKeys.privateKey,
  clientAddress: peer.address,
  serverPublicKey: serverKeys.publicKey,
  serverEndpoint: "vpn.example.com:51820",
  dns: "1.1.1.1",
  persistentKeepalive: 25,
})

await generateClientQRCode(clientConfig, {
  outputPath: "/tmp/client.png",
})

await up("wg0")
```

`generateKeys()` keeps keys in memory. Pass `privateKeyPath`, `publicKeyPath`, or `keyPath` only when files should be written; generated files use mode `0600`.

## Peer address allocation

`addPeer()` reads the server config and allocates the first free address from the matching `Interface.Address` subnet.

- IPv4 peers receive a `/32`.
- IPv6 peers receive a `/128`.
- The default family is IPv4 when an IPv4 interface address exists.
- Use `family` to select IPv6.
- Use `addressPool` to override the subnet used for allocation.
- Provide `allowedIPs` to set peer routes explicitly; the first route is also used for the returned address metadata.

```ts
const ipv6Peer = await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: clientKeys.publicKey,
  family: "ipv6",
})

const routedPeer = await addPeer("/etc/wireguard/wg0.conf", {
  publicKey: anotherClientKey,
  allowedIPs: ["10.0.0.50/32", "192.168.10.0/24"],
})
```

## Apply changes safely

Configuration helpers write files atomically. Peer helpers accept these options:

```ts
type SyncOptions = {
  iface?: string
  sync?: boolean | "auto"
}
```

- `sync: false` only updates the file.
- `sync: true` updates the file and runs `syncConf()`.
- `sync: "auto"` or omitting `sync` syncs only when the interface is already running.
- `iface` overrides the interface name derived from the filename.

`writeConfig()` does not sync the interface automatically. Call `syncConf(iface)` after using it on a running tunnel.
