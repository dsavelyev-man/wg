# generateKeys

Generate a WireGuard private/public key pair with `wg genkey` and `wg pubkey`.

## Signature

```ts
generateKeys(options?: {
  privateKeyPath?: string
  publicKeyPath?: string
}): Promise<{
  publicKey: string
  privateKey: string
  privateKeyPath?: string
  publicKeyPath?: string
}>
```

## Basic usage

```ts
import { generateKeys } from "@kriper0nind/wg-utils"

const { privateKey, publicKey } = await generateKeys()
```

Keys are kept in memory by default. No files are written unless paths are supplied.

## Write key files

```ts
const keys = await generateKeys({
  privateKeyPath: "/etc/wireguard/server.key",
  publicKeyPath: "/etc/wireguard/server.pub",
})

console.log(keys.privateKeyPath)
console.log(keys.publicKeyPath)
```

When paths are provided:

- Parent directories are created recursively.
- Files are written with mode `0600`.
- The returned object includes the written paths.

Keeping the public key at mode `0600` is intentional; it is safe to relax permissions separately if needed.

## Typical server setup

```ts
import { generateKeys, initConf, up } from "@kriper0nind/wg-utils"

const serverKeys = await generateKeys()

await initConf("/etc/wireguard/wg0.conf", {
  privateKey: serverKeys.privateKey,
  ip: "10.0.0.1",
  port: 51820,
})

await up("wg0")
```

## Key format

WireGuard keys are 32-byte base64 strings. The library validates generated keys with the equivalent of:

```ts
;/^[A-Za-z0-9+/]{43}=$/
```

## Errors

- `WgNotFoundError` when the `wg` executable is unavailable
- `ConfigValidationError` when generated output is not a valid key
- Node.js file-system errors when key files cannot be written
