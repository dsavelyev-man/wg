# Working with Configs

Use the configuration API to read, validate, update, and write WireGuard files without manually handling their formatting.

## Core functions

```ts
import {
  getPeer,
  getInterfaceName,
  listDisabledPeers,
  listPeers,
  readConfig,
  removePeer,
  setPeerEnabled,
  updatePeer,
  validateWireGuardConfig,
  writeConfig,
} from "@kriper0nind/wg-utils"
```

## Read and write

```ts
import { readConfig, writeConfig } from "@kriper0nind/wg-utils"

const config = await readConfig("/etc/wireguard/wg0.conf")
config.Interface!.ListenPort = 51821

await writeConfig("/etc/wireguard/wg0.conf", config, {
  backup: true,
  createDirectory: true,
  mode: 0o600,
})
```

`writeConfig()` validates and serializes the configuration, then replaces the file atomically. It returns the generated text.

Write options:

- `createDirectory?: boolean` defaults to `true`
- `backup?: boolean` creates `<filepath>.bak-<timestamp>` before replacing
- `mode?: number` defaults to `0o600`

`writeConfig()` does not apply the configuration to a running interface. Use `syncConf(iface)` afterwards.

## Validate

```ts
import { readConfig, validateWireGuardConfig } from "@kriper0nind/wg-utils"

const config = await readConfig("/etc/wireguard/wg0.conf")
validateWireGuardConfig(config)
```

Validation checks interface CIDRs, listening ports, peer public keys and duplicates, `AllowedIPs`, endpoint structure, and persistent keepalive values.

## Inspect peers

```ts
import { getPeer, listDisabledPeers, listPeers } from "@kriper0nind/wg-utils"

const activePeers = await listPeers("/etc/wireguard/wg0.conf")
const disabledPeers = await listDisabledPeers("/etc/wireguard/wg0.conf")
const peer = await getPeer("/etc/wireguard/wg0.conf", "peer-public-key")
```

- `listPeers()` returns active peers only.
- `getPeer()` returns a peer or `undefined`.
- `listDisabledPeers()` reads blocks disabled by `setPeerEnabled()`.

## Update a peer

```ts
import { updatePeer } from "@kriper0nind/wg-utils"

await updatePeer(
  "/etc/wireguard/wg0.conf",
  "peer-public-key",
  {
    PersistentKeepalive: 25,
    Endpoint: "vpn.example.com:51820",
  },
  { sync: true },
)
```

Use `null`, `undefined`, or `""` to remove a field:

```ts
await updatePeer("/etc/wireguard/wg0.conf", "peer-public-key", {
  Endpoint: null,
})
```

Configuration writes default to `sync: "auto"` for peer helpers.

## Enable and disable peers

```ts
import { setPeerEnabled } from "@kriper0nind/wg-utils"

await setPeerEnabled("/etc/wireguard/wg0.conf", "peer-public-key", false)
await setPeerEnabled("/etc/wireguard/wg0.conf", "peer-public-key", true)
```

Disabling prefixes every line of the peer block with `#wg-utils: `. Re-enabling removes that prefix without losing the original configuration.

The function returns:

- `true` when the state changed
- `false` when the peer was already in the requested state

## Remove a peer

```ts
import { removePeer } from "@kriper0nind/wg-utils"

const removed = await removePeer("/etc/wireguard/wg0.conf", "peer-public-key")
```

Removal is idempotent and returns `true` only when a matching active or disabled peer block was removed.

## Raw config text and comments

`readConfig()` parses the file into `WireGuardConfig`. Parsing ignores comments and does not preserve them in the resulting object. For peer updates, prefer `updatePeer`, `setPeerEnabled`, `removePeer`, and `deletePeer` because they edit the original text and preserve unrelated blocks and comments.

## File permissions

Configuration files are written with mode `0600` by default. On Unix systems, interface management generally requires root privileges, so write files with the same privileges that will start the interface.
